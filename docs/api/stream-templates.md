# Stream templates API and `/templates` page

Reference for the stream-template endpoints and the Templates page that consumes
them. Scope:
[`app/api/streams/template/route.ts`](../../app/api/streams/template/route.ts) and
[`app/templates/page.tsx`](../../app/templates/page.tsx).

## Overview

A **stream template** is a reusable preset for creating a stream: an asset, a
rate, an interval, and an optional memo. The Templates page lists presets,
sorts them into categories, and hands the chosen preset to `/streams/new`
through query parameters.

> **Persistence caveat:** templates are held in a module-scoped
> `Map<string, StreamTemplate>` inside the route handler. They are **in memory
> only**:
>
> - every server restart, redeploy, or scale-to-zero cold start discards all
>   templates;
> - separate serverless instances (and separate `next dev` workers) have
>   independent Maps, so a template created on one instance is not visible on
>   another;
> - the store is not per-user, is not authenticated, and is not backed by
>   Supabase.
>
> This is suitable for demos and local development, not for durable user data.

## Data model

```ts
interface StreamTemplate {
  id: string;                 // "tpl_<Date.now()>" — server-generated
  name: string;               // trimmed
  asset: string;              // e.g. "USDC" or "XLM"
  amountPerInterval: number;  // expected > 0
  intervalSeconds: number;    // expected > 0
  memo?: string;
  createdAt: string;          // ISO 8601, server-generated
}
```

## Endpoints

### `GET /api/streams/template`

Returns every template the current instance holds.

**Response — `200 OK`**

```json
{
  "templates": [
    {
      "id": "tpl_1727000000000",
      "name": "Weekly savings",
      "asset": "USDC",
      "amountPerInterval": 25,
      "intervalSeconds": 604800,
      "memo": "roundup",
      "createdAt": "2026-09-24T09:00:00.000Z"
    }
  ]
}
```

`templates` is always present and is `[]` when nothing has been created. Order
is the Map's insertion order, i.e. creation order. The endpoint takes no query
parameters and has no pagination.

### `POST /api/streams/template`

Creates a template. There is **no authentication or authorization check**, and no
per-user scoping.

**Request body (JSON)**

| Field | Type | Required | Validation |
|---|---|---|---|
| `name` | `string` | yes | Non-empty after trimming |
| `asset` | `string` | yes | Must be a string; not checked against a token allowlist |
| `amountPerInterval` | `number` | yes | Must be truthy and coerce to a number `> 0` |
| `intervalSeconds` | `number` | yes | Must be truthy and coerce to a number `> 0` |
| `memo` | `string` | no | Stored verbatim |

`id` and `createdAt` are always generated by the server; client-supplied values
are ignored.

**Response — `201 Created`**

```json
{
  "template": {
    "id": "tpl_1727000000000",
    "name": "Weekly savings",
    "asset": "USDC",
    "amountPerInterval": 25,
    "intervalSeconds": 604800,
    "memo": "roundup",
    "createdAt": "2026-09-24T09:00:00.000Z"
  }
}
```

**Validation and error codes**

Every error uses the envelope `{ "error": { "code": string, "message": string } }`.

| HTTP | `code` | Cause |
|---|---|---|
| `400` | `INVALID_JSON` | The body is not parseable JSON |
| `400` | `MISSING_NAME` | `name` is absent, not a string, or blank after trimming |
| `400` | `MISSING_ASSET` | `asset` is absent or not a string |
| `400` | `INVALID_AMOUNT` | `amountPerInterval` is falsy or coerces to `<= 0` |
| `400` | `INVALID_INTERVAL` | `intervalSeconds` is falsy or coerces to `<= 0` |

Checks run in the order above, so a request missing several fields reports only
the first failure.

Numeric fields are coerced with `Number(...)` and rejected only when they are
falsy or coerce to a value `<= 0`. A non-numeric string such as `"abc"` passes
the guard and is stored as `NaN`; because `NaN` has no JSON representation it is
serialised back as `null` on later `GET`s. Validate numeric input before posting
if you depend on these fields being numbers.

### Routes that do not exist

The route module's header comment also mentions
`GET /api/streams/template/[id]` "handled in [id]/route.ts". No such file exists
in this repository — only the collection route above is implemented. There is no
update or delete endpoint, so a template cannot be removed through the API.

## The `/templates` page

`app/templates/page.tsx` is a `"use client"` page that fetches
`GET /api/streams/template` on mount and re-fetches whenever Retry is pressed.

### Page states

| State | Trigger | UI |
|---|---|---|
| `loading` | Initial render and every retry | Skeleton grid, `aria-busy="true"` |
| `populated` | Response with ≥ 1 template | Category tabs, search box, template grid |
| `empty` | Response with 0 templates | Category tabs, search box, and the "No templates found" empty state |
| `error` | Non-OK response or network failure | `PageError` with a Retry button that re-fetches |

An aborted fetch (component unmount) is ignored and does not move the page into
the error state.

### Category heuristics

The category is derived from the lower-cased `name` **plus** the lower-cased
`memo`, matched as substrings and evaluated in this order:

| Category | Matches when the text contains |
|---|---|
| `savings` | `savings`, `invest`, `roundup` |
| `income` | `income`, `freelance`, `salary`, `earn` |
| `bills` | `bill`, `utility`, `payment` |
| `custom` | anything else (fallback) |

Because the checks are ordered and use `includes`, the first match wins: a
template named "Salary bill payment" is `income`, not `bills`. Categorisation is
client-side only; it is neither sent to nor returned by the API. The `All` tab is
not a category — it disables the filter.

### Search

The search box filters the already-fetched list, case-insensitively, on `name`,
`memo` **and** `asset`. Category and search filters compose: a result must match
both.

### Apply query parameters

"Use template" navigates to:

```
/streams/new?templateId=<id>&asset=<asset>&rate=<amountPerInterval>&interval=<intervalSeconds>&memo=<memo>
```

| Parameter | Source | Notes |
|---|---|---|
| `templateId` | `template.id` | Identifies the preset that was chosen |
| `asset` | `template.asset` | Passed through verbatim |
| `rate` | `String(amountPerInterval)` | Numeric string |
| `interval` | `String(intervalSeconds)` | Numeric string |
| `memo` | `template.memo ?? ""` | Always sent; empty string when unset |

Values are serialised with `URLSearchParams`, so they are percent-encoded.
How `/streams/new` consumes these parameters is out of scope for this document.
